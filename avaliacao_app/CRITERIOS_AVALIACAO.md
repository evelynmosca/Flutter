# Critérios da Avaliação Somativa PPDM

Matriz baseada no PDF **Avaliação Somativa PPDM 3DSMB20.pdf**. O aplicativo tem seis telas, uma API de produtos em processo separado com banco SQLite e uma consulta adicional ao ViaCEP. O banco entregue contém produtos demonstrativos. A API precisa estar ligada para o aplicativo consultar ou alterar produtos.

**Leitura dos status:** “Implementado e testado” indica que há código e uma verificação executada; a coluna de evidência informa seu alcance. “Implementado, mas não testado” indica código disponível sem verificação completa nesta rodada. “Depende de ação do aluno” identifica atitudes, apresentação ou registros pessoais que o projeto não pode comprovar. Testes isolados do cliente HTTP com `MockClient` e testes reais do servidor não equivalem, por si sós, a um teste visual de ponta a ponta no aplicativo.

## Limites da verificação atual

Em 28/10/2026 passaram `flutter pub get`, `flutter analyze`, `flutter test` (7/7), os testes HTTP/SQLite do backend (3/3), `flutter build web`, `flutter build apk --debug` e `flutter install --debug -d emulator-5554`. O APK atualizado abriu no emulador. A API local respondeu ao GET com três produtos; as capturas reais `evidencias/chrome_catalogo.png` e `evidencias/android_catalogo.png` mostram o catálogo carregado no aplicativo. POST, PUT e DELETE foram executados pela interface Android contra o backend real: o produto de teste foi criado, teve o preço atualizado e depois foi excluído. As telas resultantes estão em `evidencias/produto_criado.xml`, `evidencias/produto_editado.xml` e `evidencias/produto_excluido.xml`, e o estado do servidor foi conferido por GET/SQLite. O contato salvo no armazenamento seguro reapareceu após `adb shell am force-stop` e `am start`, conforme `evidencias/reinicio_android.png`, `evidencias/reinicio_android.xml` e `evidencias/contato_apos_reinicio.xml`. A consulta real ao ViaCEP para `01001000` retornou endereço em São Paulo, conforme `evidencias/cep_resultado.png` e `evidencias/cep_resultado.xml`. Os testes Flutter do cliente REST usam `MockClient`; os testes do backend usam HTTP real e reiniciam o servidor para verificar o SQLite. A pasta `integration_test` foi retirada a pedido do aluno, pois não é necessária para executar o aplicativo. Portanto, não há suíte de integração visual automatizada no projeto atual. Nenhuma captura antiga que não esteja no workspace é citada como evidência disponível.

Em 09/11/2026, `flutter pub get`, `flutter analyze`, `flutter test` (7/7), `python backend/test_servidor.py` (3/3), `flutter build web` e `flutter build apk --release` passaram. O APK de release na raiz foi instalado no Pixel 9 com `adb install -r` e carregou quatro produtos da API; o Chrome carregou o mesmo catálogo. As evidências são `evidencias/pixel9_release.png`, `evidencias/pixel9_release.xml` e `evidencias/chrome_catalogo_atual.png`. A API Python estava ativa nos testes; o APK sozinho não inicia um servidor no computador. Um celular físico e uma API hospedada fora do computador não foram testados.
